THE BUG:
────────
File: remediation_engine/ai/inference.py
Line: 126
Problem: Hardcoded health_url_template="http://localhost:8000/health"

This caused health checks to ALWAYS fail after container restarts because:
  - "localhost" inside a Docker container refers to the container itself
  - NOT the api_service container on the Docker network
  - So it was trying to connect to itself instead of api_service

═══════════════════════════════════════════════════════════════════════════════

THE FIX:
────────
Changed line 126 from:
  health_url_template="http://localhost:8000/health"  ❌

To:
  health_url_template=None  ✅

Now it uses the environment variable HEALTH_URL_TEMPLATE which is correctly set to:
  http://{container}:8000/health

This gets formatted as:
  http://api_service:8000/health  ✅

═══════════════════════════════════════════════════════════════════════════════

WHY IT LOOKED LIKE IT WORKED BEFORE:
─────────────────────────────────────
The old logs showed "localhost" and it worked. This was probably because:
  1. The containers were on host network mode (not bridge)
  2. OR the api_service was running on the host, not in Docker
  3. OR you were testing from outside Docker where localhost works

But in the current Docker Compose setup with bridge networking, containers
must use service names (api_service) to communicate, not localhost.

═══════════════════════════════════════════════════════════════════════════════

WHAT WAS HAPPENING:
───────────────────
1. AI detects error (500, 503, etc.) ✅
2. Decision engine restarts api_service container ✅
3. Health check tries to verify recovery ❌
4. Connects to http://localhost:8000/health (WRONG!)
5. Connection refused (because localhost = itself, not api_service)
6. Health check fails 10 times
7. Marks recovery as "UNVERIFIED" (false positive)

═══════════════════════════════════════════════════════════════════════════════

WHAT WILL HAPPEN NOW:
─────────────────────
1. AI detects error (500, 503, etc.) ✅
2. Decision engine restarts api_service container ✅
3. Health check tries to verify recovery ✅
4. Connects to http://api_service:8000/health (CORRECT!)
5. Gets {"status": "healthy"} response ✅
6. Health check succeeds on attempt 1-2
7. Marks recovery as "VERIFIED" (true positive) ✅
